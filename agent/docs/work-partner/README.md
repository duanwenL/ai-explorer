# 工作伙伴源码导读：分八部分学习

这份导读把 MindPad 工作伙伴拆成八个小问题。每次只读一部分，看懂指定的几行代码，再进入下一部分。这里的八部分是教学划分，不是 MindPad 官方模块数量。

## 怎么学

1. 先读本节的“只解决这个问题”和具体例子。
2. 只打开本节指定的函数或行号，不从大文件第一行一直读到最后。
3. 用自己的话回答“读懂的标准”。回答不出来就停在这一节，不必继续往下看。
4. 想继续讲解时，在聊天中说“讲第 1 部分”“第 3 部分没懂”或“继续下一部分”。

每节的例子是帮助理解的假设场景，不代表已经执行过这些工作。本导读只需要阅读代码，不需要启动 MindPad、配置模型 API 或调用付费模型。

## 第一阶段：看懂模型和工具的基础

### [第 1 部分：一个伙伴到底是什么？](01-partner-config.md)

只学模型、指令、工具配置如何组成一个 Agent。先对照自己的 `session.mjs`，再看 MindPad 如何取得伙伴配置。

读懂后能说清：换模型、改指令和加工具，分别改变什么。

### [第 2 部分：工具怎样交给模型，再由程序执行？](02-tools.md)

只学工具名称、描述、参数定义和 `execute()` 的区别，以及“注册工具”与“允许使用工具”的区别。

读懂后能说清：模型为什么可以选工具，但真正执行工具的是代码。

## 第二阶段：看懂一条消息怎样变成一次工作

### [第 3 部分：用户消息怎样到达执行服务？](03-message-entry.md)

只跟一条普通网页消息，看前端、Java 代理与 Node.js 运行服务分别做什么。

读懂后能说清：前端的 `new_task` 为什么不等于立刻创建独立业务工作。

### [第 4 部分：聊天与独立工作有什么区别？](04-business-task.md)

只看 `conversation.work` 的 `start` 分支和 `TaskDoc` 业务任务记录。

读懂后能说清：接纳任务、排队执行、工作完成是三件不同的事。

### [第 5 部分：一次工作怎样进入模型与工具循环？](05-execution-loop.md)

只看 `Kernel` 配置会话、`TaskExecutor` 准备输入，以及 `submit()`、`wait()`。

读懂后能说清：哪些过程由 MindPad 业务代码组织，哪些过程由 `pi-durable` 执行。

## 第三阶段：看懂做一半、交成果和服务重启

### [第 6 部分：缺资料时，怎样问用户再继续？](06-ask-human.md)

只看 `ask_human` 和 `waiting_input`，理解“本次原生执行结束”与“业务工作完成”的区别。

读懂后能说清：用户回答之后，为什么继续的是原工作。

### [第 7 部分：为什么有回复还不一定算完成？](07-delivery.md)

只学候选结果、成果文件、完成条件和交付版本。

读懂后能说清：文字说“完成了”、文件已登记、工作满足要求、外部发送成功，分别需要什么证据。

### [第 8 部分：状态存在哪里，重启后怎样处理？](08-persistence.md)

只学 SQLite、命令与请求编号，以及重启恢复和外部操作结果未知时的限制。

读懂后能说清：可以恢复会话状态，不意味着可以安全重做每一次外部操作。

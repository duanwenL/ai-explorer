# 后续练习：让程序计算 18 × 7

这个项目用一个很小的例子，演示 **Agent 如何调用工具、取得结果并保存会话**。

Agent 在这里指：把问题交给模型，执行模型要求调用的工具，再把工具结果交回模型，直到得到回答的程序。

你现在只需要理解一件事：**模型提出要做什么，JavaScript 工具代码真正执行，框架把整个过程连接起来。**

[工作伙伴源码导读：八部分学习目录](docs/work-partner/README.md)保留为后续参考。等框架基础和动手练习掌握后，再对照 MindPad 的真实实现；当前学习不需要阅读它。

## 2. 一次计算到底发生了什么？

### 第一步：程序提交问题

用户输入是“请用工具计算 18 × 7。”。

入口是 [src/demo.mjs](src/demo.mjs)。它创建演示用的模型来源，打开会话，然后调用 `runInput()` 提交问题。

### 第二步：模型输出一个工具调用

模型输出的意思是：

- 工具名称：`calculate`。
- `operation` 是 `multiply`，表示乘法。
- `a` 是 `18`。
- `b` 是 `7`。

这里的输出不是 JavaScript 代码，而是一条包含工具名称和参数的数据。框架根据名称找到程序注册的工具。

**当前 demo 的这条模型输出是预先写好的。** 你先用它看清执行过程，不需要购买或配置聊天模型。

### 第三步：工具真的计算

工具定义在 [src/calculator.mjs](src/calculator.mjs)。

它的 `execute(args)` 方法拿到刚才的参数，用 JavaScript 执行乘法，得到 `126`，再把结果返回给框架。

真正算出 `126` 的是这里的代码。工具目前只支持两个整数的加法和乘法，整数绝对值最大为一百万。

### 第四步：模型读取工具结果，再给出回答

框架把 `126` 放入后续模型输入，再调用一次模型。

演示里的第二条预设模型输出会读取这次实际工具结果，然后返回：

“18 × 7 = 126。结果来自 calculate 工具。”

因此，回答虽然使用预设格式，但数值来自真正执行的工具。它不是绕过工具直接返回固定的 `126`。

### 第五步：保存会话

框架把会话执行记录保存在 `agent/data/demo.sqlite`。

SQLite 是保存在本机文件里的数据库，运行本例不需要启动 MySQL 或 Redis，也不需要为它启动 Docker。

**这一轮有两次模型请求、一次工具执行。** 第一次模型请求提出工具调用，第二次根据工具结果生成回答。

## 4. 只按这个顺序看文件

### ① `src/demo.mjs`：从哪里开始？

先看这个入口文件。它做五件事：

1. 创建演示用的模型来源。
2. 指定 SQLite 文件位置。
3. 调用 `openLearningAgent()` 打开会话。
4. 调用 `runInput()` 提交问题并取得结果。
5. 打印结果，最后关闭运行资源。

文件里的 `trace` 就是打印执行日志的函数，帮助你看清每一步。

### ② `src/calculator.mjs`：程序具体会做什么？

这个文件定义唯一的计算工具：

- `name`：框架用它找到对应工具。
- `description`：告诉模型这个工具能做什么。
- `parameters`：描述允许的操作、参数类型和数值范围。
- `execute`：真正执行加法或乘法的方法。
- `replay: 'safe'`：声明纯计算可以安全重跑。付款、发消息等会影响外部系统的工具不能直接照抄这个声明。

你先重点看 `execute`。如果后续加一个“查询订单”工具，具体的查询逻辑也应该放在它自己的执行方法里。

### ③ `src/providers.mjs`：模型输出从哪里来？

`createDemoProvider()` 返回预设模型输出，用于本例。它第一次要求调用工具，第二次读取工具结果并回答。

`createChatProvider()` 负责连接外部聊天模型，等你理解演示后再看这一部分。

这里的 provider 可以理解为“取得模型输出的接口”。演示模式从预设代码取得输出，真实模式从外部模型 API 取得输出。

### ④ `src/session.mjs`：这些部分怎么连接起来？

这个文件是执行核心，你先看两个方法即可。

**`openLearningAgent()`：准备运行环境。**

它注册模型来源、注册计算工具、打开 SQLite，创建框架运行实例，并设置使用哪个模型、给模型什么说明、允许使用哪些工具。

**`runInput()`：完成一次用户请求。**

它检查问题长度，提交输入，等待执行结束，再从会话记录中读取最终回答，返回回答文字和请求记录 ID。

项目使用 `@earendil-works/pi-durable` 作为 Agent 执行框架。模型提出工具调用之后，框架负责执行工具、记录结果并继续请求模型，所以业务代码里没有自己写一大段循环。

### ⑤ `tests/session.test.mjs`：怎么证明不是只打印了几行字？

这个测试真的打开临时 SQLite，执行计算，然后关闭并重新打开。

它检查：

- 回答里确实有 126。
- 第一次确实发生两次预设模型请求。
- 第二次模型输出确实读到了工具结果。
- 重新打开后，相同请求 ID 返回原结果，没有再次请求预设模型。

## 5. 第二次运行，为什么可能没有计算日志？

演示使用固定请求 ID：`demo-multiply-v1`。

再次执行相同命令时，框架可以直接读取已经保存的结果，终端会显示“已从 SQLite 复用同一请求的结果，没有重复执行”。这用来演示同一请求的结果复用，不是程序没有运行。

这里要区分两件事：

- 会话历史保留：关闭程序再打开，之前的消息仍然存在。
- 同一请求结果复用：相同请求 ID 可以取回已有结果。

仅把问题文字写得一样，不代表它就是同一请求。真实聊天入口 `chat.mjs` 每次生成新的请求 ID，相同问题也会作为新请求提交。

如果以后修改这个固定演示，要同时调整问题、预设工具参数、回答格式和请求 ID。仅修改问题文字，预设模型仍会调用原来的 18 × 7；沿用旧请求 ID，还可能直接读回旧结果。

## 6. 真实模型、Maven 和 RAG 分别是什么关系？

### 真实模型入口

[src/chat.mjs](src/chat.mjs) 使用真实聊天模型。它与 demo 共用会话和工具执行代码，区别是输出来源改为外部模型 API。

需要单独配置 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`，并使用支持工具调用的模型；调用可能产生费用。它不会复用文档向量模型的密钥。

初学阶段先把 demo 理解清楚，再接真实模型。

### Maven 管理方式

项目业务代码是 JavaScript，`.mjs` 是 JavaScript 模块文件，由 Node.js 执行。

根 Maven 工程统一负责安装 Node.js、安装锁定的 JavaScript 依赖、执行测试、代码检查和演示。它没有把这些文件改写成 Java，也没有把 Agent 打包成 Spring Boot JAR。

### 与文档检索模块的关系

当前 `agent` 和 `rag` 是两个独立模块。这个计算演示还没有调用文档检索，也没有实现 MindPad 完整工作伙伴的界面、权限或任务系统。

以后可以把文档检索做成一个工具：模型提出检索请求，工具调用 RAG 的检索接口，把命中文本返回给模型，再由模型组织回答。
